# DECISIONS

Consequential decisions with rationale. Detailed architecture decision records live in
`docs/adr/`. This file is the running index.

| # | Decision | Rationale | ADR |
|---|----------|-----------|-----|
| D-01 | Extend the existing repository rather than rewrite it. The wheel-strategy decision-support dashboard (milestones 1–10, 951 passing tests) is kept intact; the deterministic strategy platform is added as new `chronos.*` subpackages. | The existing code already embodies the required safety posture (hard-disabled orders, fail-closed reconciliation, Decimal money). Rewriting would destroy tested invariants. | ADR-0001 |
| D-02 | Interactive Brokers API access stays on the TWS API via `ib_async`. | Already a dependency; actively maintained community successor to ib_insync; TWS API supports paper accounts, what-if orders, executions, and account events. Client Portal Web API rejected for session-keepalive complexity and weaker order-event semantics for this use case. | ADR-0002 |
| D-03 | The new platform persists to its own SQLite database file (separate from the wheel ledger), append-oriented tables, schema versioned. | The existing schema v2 binds a database file to one account fingerprint with strict adoption rules; mixing platform state into it would weaken those invariants. | ADR-0003 |
| D-04 | Strategy code emits `StrategyProposal` objects only; a separate portfolio layer converts proposals to sized `OrderIntent`s; an independent risk engine validates every intent deny-by-default; only the execution layer talks to a broker adapter. | Required separation of authority; strategies cannot see broker or risk internals. | ADR-0004 |
| D-05 | Event-time simulation and live paths share one deterministic engine loop; all timestamps UTC internally; bars are processed only when closed (confirmed), matching Pine `barstate.isconfirmed` semantics with `calc_on_every_tick=false`. | Reproducibility and Pine parity; eliminates intrabar repainting class of bugs by construction. | ADR-0005 |
| D-06 | Backtest fills model: signals computed on bar close t, orders filled at bar open t+1 with configurable slippage and commission; no same-bar fills. | Conservative, replicable, matches how the daily-bar strategies would actually be traded; avoids look-ahead. | ADR-0005 |
| D-07 | Research data acquired from public dataset mirrors through authenticated connector access, with per-file provenance, hashes, and integrity validation recorded. IBKR historical data is the intended production source once the owner supplies credentials. | Direct market-data vendor endpoints are unreachable from this build environment. | ADR-0006 |
| D-08 | Operating modes RESEARCH/BACKTEST/REPLAY/SHADOW/PAPER/CANARY_LIVE/LIVE implemented as a runtime mode lock with multi-condition activation; CANARY_LIVE and LIVE are implemented as *recognized but refused* states **in this deterministic platform's mode lock** (`chronos.control.modes`), which still raises unconditionally and is untouched by ADR-0016. *(Scoped 2026-07-25: the separate `chronos.orders` plane gained a gated live branch in Milestone 7 — ADR-0009 — so the original phrase "the live submission path raises unconditionally in this codebase version" is no longer true repository-wide.)* | One mistyped variable must not enable live trading; refusing in code beats configuration. | ADR-0007 |
| D-09 | Halt (kill-switch) state persists in the platform database and must be cleared by an explicit operator rearm command; process restart re-enters reconciliation and keeps the halt. | Restart must never clear a risk halt. | ADR-0007 |
| D-10 | Pine corpus fetched from Notion (owner's authoritative store) into `research/pine/`, SHA-256 hashed; audits and registry reference hashes, not page URLs alone. | Reproducibility of the audit against exact sources. | — |
| D-11 | ~~No generative model output feeds any runtime decision. AI was used to author code, audits, and documentation offline; every runtime path is deterministic, versioned, and tested.~~ **SUPERSEDED by D-16 (2026-07-25).** Kept for history; read it as the posture through that date, not as current policy. | Was: non-negotiable rule in the build brief. Superseded by an explicit owner directive re-scoping Chronos as an autonomous, model-driven system. | ADR-0004 §5 (superseded by ADR-0016) |
| D-12 | Initial executable candidates limited to daily-bar, long-only ETF strategies derived from the corpus (Markov regime-gated trend continuation family; RSI-2-class mean-reversion family), validated against simple baselines; intraday corpus scripts classified research-only. | Account size (~USD 3k), PDT constraints, data availability, and cost floor make intraday untradeable for this account; honesty over ambition. | ADR-0008 |
| D-13 | IBKR historical bars are ingested by a separate, read-only data process (`chronos.histdata`, own `ib_data_client_id`) into a file store of **unadjusted** bars plus a corporate-action event stream; adjusted / total-return views are derived at read time and never written back. The process is structurally isolated — it opens no trading database, holds no writer lease, and imports no order/broker module (AST + subprocess import tests forbid the order plane and `sqlalchemy`/`sqlite3`; `ibapi` stays lazy). Succeeds D-07's approximation of following the source's adjusted series. | Retroactive re-adjustment would break hash-pinned provenance; a data process that could place an order or hold the lease would be catastrophic; the real fetch is owner-gated (invariant 8) and built against a fake in CI. | ADR-0011 |
| D-14 | The same read-only data process captures **forward** option-chain / IV / greeks EOD snapshots (`python -m chronos.histdata options`) for allowlisted underlyings into immutable per-day files, over a **bounded** window (expiry horizon + strike band of spot, both recorded in the snapshot). Every row carries its quote's `DataQuality`, and each snapshot records a staleness histogram — $0-tier delayed/EOD data is labeled, never presented as live. No greeks/IV are fabricated (absent ⇒ `None`); the store ships empty; the real fetch is owner-gated. | IBKR keeps **no history for expired options** — there is no backfill at any price, so forward capture must start ASAP; honest staleness labeling and recorded capture bounds keep a delayed/partial snapshot truthful rather than misleading. | ADR-0012 |
| D-15 | Research runs and holdout events are recorded in a tamper-evident, hash-chained registry ledger (`chronos.registry`, reusing `auditlog`) with an out-of-band **head anchor** so truncation/deletion is caught; it is the source of truth for the multiple-testing **trial count** (derived from registered runs) and for which holdout windows are **burned**. Consuming a holdout requires an owner-typed, **single-use, file-locked, logged** unlock (module-constant phrase via `hmac.compare_digest`, never a setting/logged), rationed by a data-accrual budget; the guardian **verifies the ledger before trusting it** and fails closed, so re-using a burned window as "fresh" (incl. via truncation) is detected and refused. The registry is research-plane (opens no trading DB, imports no order/broker); no shipped scheduled/service/control/execution/orders/runtime path imports or calls the unlock (AST + single-unmask-site tests), model plane barred (written prospectively against `chronos.copilot`; **retargeted by D-16**: `chronos.autonomy` joins the scanned automated tree, so the model plane cannot import the registry or call the unlock — the guarantee ADR-0013 §7 actually makes, preserved. The converse half — forbidding the automated tree from *importing* the model plane — is deliberately not applied to `chronos.autonomy`, because D-16's deterministic supervisor must import the decision contract in order to judge it; it remains in force against the never-built `chronos.copilot`). | The M5 review's "burned holdout" failure — a holdout silently reused as fresh — must be detected and refused, and self-reported trial counts are theater; a hash-chained + anchor-verified ledger and a once-only owner-typed unlock make both auditable and enforced in code. Honest residuals (both-files rewrite, runtime-reflection evasion, trial-count completeness) are recorded in ADR-0013 §11 / limitations. | ADR-0013 |
| D-16 | **An approved generative model may originate runtime trading decisions only through a typed AITradeDecision and the single deterministic ModelDecisionGateway. The model cannot access IBKR directly, change its authorization, weaken policy, or bypass any deterministic gate.** Trade-time authority is granted by an owner-authored, versioned, expiring, revocable AutonomyMandate; policy-time control (objectives, model/provider versions, permitted instruments and strategies, capital and risk allocation, promotion, activation/revocation, kill switch) stays with the owner. The deterministic kernel keeps unconditional veto authority and every guarantee in ADR-0016 §8 is unweakened. Supersedes D-11. | Owner directive (2026-07-25) re-scoping Chronos as a fully autonomous, model-driven trading system. The hazard D-11 addressed by prohibition is now addressed by structure: one decision type, one gateway, one transmit site, an expiring owner mandate, and an unconditional deterministic veto. | ADR-0016 |
| D-17 | **Maximal autonomy, owner-directed.** A persistent mandate file (`AUTONOMY_MANDATE_FILE`) auto-activates on every boot — a running backend plus a valid, account-matching mandate is enough to trade, with no per-boot ritual (supersedes ADR-0016 §4 "an env var alone may not activate live"). The live-mandate ceiling moves 30d→365d and `restart_behavior` defaults to `RESUME_UNTIL_EXPIRY`. A `model_discretion` grant inverts deny-by-default **for capital ceilings only**: an unset ceiling means "affordability is the bound," while any ceiling the owner *did* set still binds. `OrderForm.MARKET` exists but compiles to a **protected** collared limit (quote±1%), never an unbounded venue `MKT`; the compiler prefers the most-aggressive *granted* form. **Not superseded:** floors/reserve, single transmit site, writer lease, kill switch, reconciliation, stale-data refusal, the full propose→preview→confirm→submit handoff, the degraded-state rule, and deny-by-default for everything the owner did not grant discretion over. Revocation survives restart; an invalid/wrong-account file boots inert with a CRITICAL alert. Closes the R-36 wiring residual. | Owner directive (2026-07-25): Chronos "as close to autonomous as possible," modeled on the reference Quant-Guild bot. "Maximal" was scoped as removing friction and owner-optional ceilings, not execution-correctness mechanisms; market orders implemented as protected rather than unbounded, with the literal-unbounded interpretation flagged as a separate un-taken decision. | ADR-0017 |
