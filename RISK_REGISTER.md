| R-25 | `max_opening_orders_per_day` is inert | H | MITIGATED (M10, 2026-07-27) | **The cap is wired and, for the first time, capable of refusing.** Two independent defects each kept it inert: `gather` never set `opening_orders_today` (so the field's `0` default made `0 + 1 <= limit` true on every call, forever), and `count_opening_since` — which had **zero callers** — additionally filtered `action == SELL`, and `OPEN ∧ SELL` is exactly `{OPEN_SHORT_PUT, OPEN_COVERED_CALL}`, so every stock and crypto opening was invisible to the cap even once wired. | R-34 | Session boundaries are calendar dates, not market sessions | M | MITIGATED (M5, 2026-07-25) | `supervisor.durable.session_key` accepts an optional `market_timezone` and converts before taking the date, so the counter rolls where the market's own day does rather than at UTC midnight — the defect being that 22:00 in New York is already the next UTC day, so a single trading afternoon straddled two counters. | R-35 | Model isolation is a code boundary, not a process boundary | H | MITIGATED (M5, 2026-07-25) | **The inversion is the fix: Chronos does not call a model — a model worker calls in.** `supervisor.ingress` accepts a JSON `ProposedDecision` from a worker running in a separate process (the owner's own AI workspace, for example). Consequently there is no provider SDK, no API key, and no egress path in the broker-holding process, and a worker that dies or is never started simply produces no decisions. The worker holds no Chronos capability — no broker handle, no session, no lease, no kill switch, no submission path — not by promise but because none was ever in its address space. The ingress treats every payload as hostile: bounded size before parsing, strict single-object JSON, NaN/Infinity refused (`NaN > limit` is False, so a naive ceiling check would pass one), bounded nesting, full contract validation, and writer-owned fields (`provenance`, `decision_id`) refused loudly rather than stripped.
