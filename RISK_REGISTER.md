| R-24 | Writer lease is never renewed in production, and is not a fencing token | C | MITIGATED (M2, 2026-07-25) | **Fixed.** The backend lifespan now runs a heartbeat that renews the lease at TTL/3 and, on any renewal failure, permanently demotes the process to read-only (re-acquiring would be unsafe — another writer may already have acted). `WriterLease.holds()` re-checks ownership **in the database** and the submission boundary calls it immediately before the transmit line, alongside the kill-switch re-read; a refusal there is provably not-sent. | R-24-orig | (historical detail of R-24) | C | CLOSED | `WriterLease.renew()` has no production caller (`grep '\.renew('` over `src/` is empty), so the 30-second lease silently expires mid-session while `BackendState.writer` stays True; a second backend can then acquire it while the first still believes it holds it. | R-29 | Autonomous model authority materially expands risk | C | OPEN (ACCEPTED, owner-directed) | ADR-0016/D-16 create the first code path by which a non-deterministic component can originate an order. | R-30 | Prompt injection into model decisions | H | OPEN (M4 scope) | Evidence derived from external text (news, filings, third-party content) is an untrusted input to a non-deterministic component; a successful injection can produce a malicious-but-well-formed `AITradeDecision`. Controls: typed decisions only (free-form text is never parsed into orders), redacted/versioned/hash-pinned EvidenceBundles, allowlisted read-only tools, and — the control that actually holds — the deterministic kernel, which independently re-derives contract, size, collateral, and every limit and can veto. Explicit malformed-output and injection tests are owed by M4 and are a frozen promotion criterion. |
| R-31 | Model repeatedly re-submitting a refused decision | M | MITIGATED (M2, 2026-07-25) | **Partly enforced.** `chronos.supervisor.admission` tracks both halves: an already-**admitted** decision id is refused as `DECISION_REPLAY`, and a **refused** one is counted, with `MAX_RESUBMISSIONS = 3` attempts before `RESUBMISSION_EXHAUSTED` refuses it permanently — so a refusal cannot be routed around by repetition. An earlier revision of this row said "enforcement lands with the gateway in M2" after the gateway had shipped, and the M2 review also found only admitted ids were tracked; both are corrected. **Durable since M3 (2026-07-25):** the counters live in `autonomy_decision_attempts` and are rebuilt by `supervisor.durable.build_state`, so a restart no longer resets the attempt budget — patience does not defeat the bound. **Residual (disclosed):** deduplication is still by `decision_id`, so a model that re-issues the *same trade* under a fresh id is not caught here; that needs economic-intent dedup and remains open. Tests: `tests/safety/test_supervisor_gateway.py`. |
| R-32 | Owner alerts have no out-of-band delivery channel | H | OPEN (promotion criterion, M3) | ADR-0016 §8 requires the system to **alert the owner** when it degrades. M3 built the durable half: `chronos.supervisor.alerts` records every alert, folds recurrences into one row so a degraded loop cannot bury the list, escalates severity but never downgrades an unacknowledged alert, and keeps acknowledgements (with a required note) forever, hash-chained. What it does **not** do is *deliver*: no email, SMS, push, or webhook. The channel is **pull**, so an owner who is not looking is not told. This is deliberate — Chronos makes no outbound network calls, and a sender holding SMTP/webhook secrets beside a trading system is the reference-project pattern the directive forbids; worse, a silently-broken push channel converts "no alerts" from *unknown* into *all clear*. A structural test (`test_the_alerting_module_opens_no_network_connection`) fails if an egress dependency is added quietly. **This gap blocks unattended `LIVE_AUTONOMOUS` promotion**: a system that can only alert someone already watching is not an unattended system. |
| R-33 | Hash chaining is tamper-evident, not tamper-proof | M | ACCEPTED (disclosed) | `chronos.persistence.hash_chain` gives the database's append-only tables the property the JSONL audit log has had since Phase 9: a targeted edit, deletion, reordering, or partial corruption breaks verification. It does **not** stop an attacker who can write to the database from recomputing every subsequent digest and presenting an internally consistent chain — no hash chain stored in the file it protects can, and the JSONL log has the same bound. Defeating a full rewrite needs an external anchor (an offsite copy of the head digest, or signing), which Chronos does not have and does not claim. Accepted because the realistic threat is corruption and casual edit, both of which are now detected. |
| R-34 | Session boundaries are calendar dates, not market sessions | M | OPEN (M4 scope) | `supervisor.durable.session_key` derives the session from the caller's datetime date, so per-session loss and activity counters roll at midnight in whatever zone the caller passes. That is correct for a UTC-keyed audit but **not** aligned to a market session: an overnight futures session spans two dates, and a US equity session in UTC rolls mid-afternoon local. The supervisor deliberately does not own a market calendar (a module that guessed one would be inventing the boundary the limits are measured across), so this must be supplied by the caller that also supplies the market clock. Until then, a mandate's session limits are day limits. Disclosed in `docs/limitations.md`. |
