| R-29 | Autonomous model authority materially expands risk | C | OPEN (ACCEPTED, owner-directed) | ADR-0016/D-16 create the first code path by which a non-deterministic component can originate an order. | R-30 | Prompt injection into model decisions | H | MITIGATED (M4, 2026-07-25) — bounded, not solved | Chronos does **not** claim to prevent prompt injection; nothing does, reliably. The claim it makes is narrower and testable: **a successful injection cannot become a trade the mandate would not otherwise have permitted.** External text arrives as `TextualEvidence`, which cannot be marked trusted, is never parsed by any deterministic module (AST-asserted), and is carried verbatim rather than sanitized — stripping it would destroy the record of what the model was actually shown. The tool surface has no write kind at all: `ToolKind` is `{READ, DECISION}`, handlers receive the evidence bundle and nothing else, the registry freezes at startup, and unknown tool names refuse rather than falling through to a near match. Injection tests assert that adversarial narrative changes no compiled order parameter byte-for-byte, does not change the decision id, and that an injected size is still clamped by the mandate. **Residual (disclosed):** an injection can still cause a differently-shaped *proposal*, which is then judged like any other — that is the design, not a gap. Process-level model isolation (R-35) is a separate, open item. |
| R-31 | Model repeatedly re-submitting a refused decision | M | MITIGATED (M2, 2026-07-25) | **Partly enforced.** `chronos.supervisor.admission` tracks both halves: an already-**admitted** decision id is refused as `DECISION_REPLAY`, and a **refused** one is counted, with `MAX_RESUBMISSIONS = 3` attempts before `RESUBMISSION_EXHAUSTED` refuses it permanently — so a refusal cannot be routed around by repetition. An earlier revision of this row said "enforcement lands with the gateway in M2" after the gateway had shipped, and the M2 review also found only admitted ids were tracked; both are corrected. **Durable since M3 (2026-07-25):** the counters live in `autonomy_decision_attempts` and are rebuilt by `supervisor.durable.build_state`, so a restart no longer resets the attempt budget — patience does not defeat the bound. **Closed in M4 (2026-07-25):** deduplication is no longer by a model-chosen id. `chronos.supervisor.queue` withholds `decision_id` from `ProposedDecision` entirely and derives it as a UUIDv5 over the proposal's **economic content**, so re-proposing the same trade yields the same id and is caught as a replay. Narrative is excluded from the digest, so rewording a thesis does not mint a fresh id and hand back the retry budget. **Remaining bound (accepted, not a hole):** a model can still get a fresh budget by proposing a genuinely *different* trade — a different size or strike. That is correct, because a different trade is a different decision and faces every gate again, including the mandate ceilings that bound total attempted exposure. Tests: `tests/safety/test_supervisor_gateway.py`. |
| R-32 | Owner alerts have no out-of-band delivery channel | H | MITIGATED (M6, 2026-07-25) — local channels only | **Delivery exists.** `chronos.supervisor.delivery` pushes unacknowledged alerts to sinks, records `delivered_at` so *told* is a different fact from *acknowledged*, and counts attempts durably so a persistently failing sink is visible rather than silently retried. Shipped sinks are a always-present log sink and an optional JSONL file sink (0600, fsync'd, `O_NOFOLLOW` per R-21) that an operator's own tooling can watch — `tail -f`, an editor watch, a systemd path unit, a desktop notifier. An alert counts as delivered when **at least one** sink accepts, so a misconfigured file path cannot suppress the log sink forever; a sink that raises is caught, because an alerting system that crashes the process it is alerting about has made things worse. `GET /autonomy/alerts` remains on the pull side. **Deliberately local-only, enforced by a structural test that fails on any network import:** a networked sender needs credentials beside a process that moves money and an egress path a compromised component could ride, and its failure mode is silence — which converts "no alerts" from *unknown* into *all clear*. **Residual (disclosed):** a local file does not follow you off the machine. Reaching a phone needs a networked channel and its own ADR, so for genuinely unattended operation away from the host this remains open. |
| R-33 | Hash chaining is tamper-evident, not tamper-proof | M | ACCEPTED (disclosed) | `chronos.persistence.hash_chain` gives the database's append-only tables the property the JSONL audit log has had since Phase 9: a targeted edit, deletion, reordering, or partial corruption breaks verification. It does **not** stop an attacker who can write to the database from recomputing every subsequent digest and presenting an internally consistent chain — no hash chain stored in the file it protects can, and the JSONL log has the same bound. Defeating a full rewrite needs an external anchor (an offsite copy of the head digest, or signing), which Chronos does not have and does not claim. Accepted because the realistic threat is corruption and casual edit, both of which are now detected. |
| R-34 | Session boundaries are calendar dates, not market sessions | M | MITIGATED (M5, 2026-07-25) | `supervisor.durable.session_key` accepts an optional `market_timezone` and converts before taking the date, so the counter rolls where the market's own day does rather than at UTC midnight — the defect being that 22:00 in New York is already the next UTC day, so a single trading afternoon straddled two counters. It is **optional and explicit**: defaulting to a guess would invent the boundary every loss and activity limit is measured across, and invent it wrongly for anyone trading elsewhere. An unknown zone **raises rather than falling back to UTC**, because a silent fallback is wrong in exactly the way nobody notices. `CycleFacts` carries it through the loop. **Residual (disclosed):** this aligns to a market's *calendar day*, not its session calendar — no holidays, no half-days, and an overnight futures session still spans two dates. For equities and equity options, the whole of the current capability matrix, a market-local day and a session coincide. Futures would need a real calendar and are not tradable. |
| R-35 | Model isolation is a code boundary, not a process boundary | H | MITIGATED (M5, 2026-07-25) | **The inversion is the fix: Chronos does not call a model — a model worker calls in.** `supervisor.ingress` accepts a JSON `ProposedDecision` from a worker running in a separate process (the owner's own AI workspace, for example). Consequently there is no provider SDK, no API key, and no egress path in the broker-holding process, and a worker that dies or is never started simply produces no decisions. The worker holds no Chronos capability — no broker handle, no session, no lease, no kill switch, no submission path — not by promise but because none was ever in its address space. The ingress treats every payload as hostile: bounded size before parsing, strict single-object JSON, NaN/Infinity refused (`NaN > limit` is False, so a naive ceiling check would pass one), bounded nesting, full contract validation, and writer-owned fields (`provenance`, `decision_id`) refused loudly rather than stripped. Refusal messages never echo payload content, so a hostile worker cannot write chosen text into operator logs. **Residual (disclosed):** authenticating *which* worker is calling is the transport's job — a Unix socket with filesystem permissions, or loopback plus the existing API token — and Chronos deliberately does not invent a second, weaker scheme. Chronos also ships no process supervisor that *starts* the worker; running it separately is an operational act. |
| R-36 | No scheduled runner drives the autonomy cycle | M | MITIGATED (M7, 2026-07-25) | **The tick exists.** `supervisor.runtime.AutonomyRuntime` drains the durable proposal queue, delivers pending alerts, and observes its own health on a time-driven tick. **Events are hints, not triggers:** `note_event()` can pull the next tick forward to the configured floor and no further, and any number of events coalesce into one early wake — so an event storm cannot become an order storm, and cycles-per-hour is a property of configuration rather than of the day's volatility. A zero floor is refused at construction. Supervision: a failing tick alerts and keeps cadence rather than dying silently (a runtime that stopped without saying so looks exactly like a runtime with nothing to do); consecutive failures past the configured bound stop the runtime with a CRITICAL alert, and restart is an operator act. The proposal route now enqueues into a bounded durable queue (newest refused at the cap, so a flood cannot erase earlier proposals) and the runtime judges on its own clock. **Residual (disclosed):** the runtime is a class, not a daemon — no shipped entrypoint constructs it with a real FactGatherer/handoff, and wiring it into the backend lifespan or a systemd unit is the operational step that remains. |
