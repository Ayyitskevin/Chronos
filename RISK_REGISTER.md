# RISK REGISTER

Living register of project and operational risks. Severity: C=critical, H=high,
M=medium, L=low. Status: OPEN / MITIGATED / ACCEPTED / CLOSED.

| ID | Risk | Sev | Status | Mitigation / Notes |
|----|------|-----|--------|--------------------|
| R-01 | Accidental live trading | C | MITIGATED (posture restated 2026-07-25) | **The blanket "no live-capable code path" claim is retired — it described the pre-M7 build.** Today: the deterministic platform's mode lock still hard-denies CANARY_LIVE/LIVE (ADR-0007, untouched by ADR-0016), but the `chronos.orders` plane *is* live-capable behind ADR-0009's nine-conjunct configuration, the ten-gate stack, arming, the durable kill switch, the drawdown breaker, and the writer lease. Under ADR-0016 live *autonomous* operation will additionally require an active owner-authored mandate — **not yet an enforced control**: no autonomy startup path, mandate store, or gateway exists (M2), so today the only thing standing between configuration and a live order is the ADR-0009 stack above. `DEFAULT_AUTONOMY_MODE` is `SHADOW` as a contract constant with no reader yet. No test, CI run, or dev path can transmit. Re-verify at every release (tests/safety). |
| R-02 | Paper/live confusion (wrong account) | C | MITIGATED | Account pattern `D[UF]\d{4,}` + operator allowlist + broker-reported environment + exact managed-accounts match before every submission window. Tested. |
| R-03 | Duplicate orders (replay, reconnect, double signal) | H | MITIGATED | Deterministic intent ids (UUIDv5 of economic content); ledger primary-key refusal; risk-engine duplicate check; sim-broker duplicate rejection; idempotent event application. Tested. Residual: cancel-replace flows are not implemented (no modify path exists). |
| R-04 | Unknown broker state after disconnect/restart | H | MITIGATED | Startup/reconnect enters non-trading state; reconciliation must pass; unknown order/position blocks trading and halts; no auto-flatten. Residual: reconciliation evidence collection against a real gateway is untested here (owner action). |
| R-05 | Risk-engine bypass by strategy code | H | MITIGATED | Structural: proposals cannot express orders; approvals are instance-token-bound; frozen policy; engine exceptions deny. Tested (forged approval, foreign engine, policy mutation). |
| R-06 | Halt cleared by restart | H | MITIGATED | Halt state is a durable file; missing/corrupt file reads as HALTED; rearm requires operator note. Tested. |
| R-07 | Look-ahead / repainting contamination in translated strategies | H | MITIGATED (for derived cores) | Closed-bar-only engine; next-bar fills; audit of every script (docs/PINE_AUDIT.md); derived strategies re-specified rather than trusting Pine defaults. Residual: no TradingView reference exports — parity is spec-level only (A-03). |
| R-08 | Research data provenance (public mirrors, not broker data) | H | OPEN (ACCEPTED for research phase) | Per-file manifests with hashes + validation + cross-checks; research conclusions carry a data caveat; owner should re-run against IBKR historical data before promotion beyond paper. **Broadened universe is heterogeneous**: SPY/QQQ unadjusted & byte-exact; IWM/TLT dividend-ADJUSTED, GLD nominal, all three markdown-transcribed (2-decimal) for 2019–2021 only (validation-window-only). Cross-symbol absolute-return comparisons are not apples-to-apples; each symbol is judged within-symbol. DIA not acquired. The re-run did not change the verdict (zero selected); disclosures in docs/RESEARCH_REPORT.md and research/selection_manifest.json. |
| R-09 | Overfitting / selection bias in strategy choice | H | OPEN | Chronological partitions, untouched final test window, baselines incl. deterministic random twin, parameter-stability review; small candidate count. Residual risk inherent to backtesting is documented in RESEARCH_REPORT. |
| R-10 | USD 3k account economics (commission drag, whole shares) | H | ACCEPTED (documented) | USD 1 minimum commission ≈ 3.3 bps/side; whole-share rounding drag modeled; results reported net. This risk alone can invalidate marginal edges. |
| R-11 | Intraday corpus strategies unvalidatable here | M | ACCEPTED | No trustworthy intraday data in this environment; scripts classified research-only, not rejected on merit (A-31). |
| R-12 | ib_async maintenance / TWS API changes | M | OPEN | Pinned range in pyproject; ADR-0002 records alternatives; adapter surface is narrow (IBLike protocol) for replaceability. |
| R-13 | SQLite durability under crash | M | MITIGATED | WAL + synchronous=FULL; ledger failure halts trading before submission; backup/restore documented. |
| R-14 | Audit-log tamper or corruption | M | MITIGATED | Hash-chained records, fsync on append, verify command, incident playbook. A corrupt final line now raises a specific `AuditLogCorruptionError` on construction (fails closed) rather than an uncaught exception (independent review H4). |
| R-20 | Halt bypass by a halt landing mid-submission (TOCTOU) | H | MITIGATED | The execution engine re-reads the halt immediately before handing the order to the broker, not only at the top of the call (independent review H1). Regression-tested. |
| R-21 | Platform state files world-readable on a shared host | M | MITIGATED | Ledger/halt/audit files (and WAL/SHM sidecars) are chmod 0600 via a symlink- and ownership-checked helper; halt write is fsync-durable (independent review M1/L1). |
| R-22 | Reconciliation is presence-only (no state-level contradiction detection) | M | MITIGATED | `reconcile()` now takes optional per-order state maps and reports `ORDER_STATE_MISMATCH` when a broker/ledger order disagrees on (lifecycle bucket, filled qty); the service startup (`chronos.service.startup`) supplies both sides and halts on any discrepancy. No auto-flatten. Tests: `tests/platform_unit/test_reconciliation.py`, `test_service.py::test_state_mismatch_halts_and_blocks`. |
| R-23 | Restart does not hydrate in-flight orders; their broker events halt and lose the evidence trail | M | MITIGATED | `ExecutionEngine.hydrate_from_ledger()` (fed by `ledger.working_order_snapshots()`) rebuilds in-flight orders at startup so a post-restart broker event applies to a real state machine and is recorded instead of triggering an evidence-losing `UNKNOWN_ORDER` halt. Tests: `tests/platform_unit/test_hydration.py`. |
| R-15 | Dependency supply chain (no lockfile) | M | MITIGATED | A hash-verified lockfile (`requirements-dev.lock`, full transitive closure with SHA-256 pins) is committed and generated from pyproject via `uv pip compile --generate-hashes`. CI and the documented deploy path (docs/DEPLOYMENT.md) install with `pip install --require-hashes -r requirements-dev.lock` then `pip install -e . --no-deps`. Residuals (M5 review): the PEP 517 build backend (`setuptools`/`wheel`) and pip itself are fetched outside the hash gate, and the owner must regenerate + review the lock diff when bumping a bound (docs/SECURITY.md). The `aeventkit` entry was verified as ib_async's genuine declared dependency, not a typosquat. |
| R-16 | Notion corpus drift vs audited hashes | L | MITIGATED | Registry pins SHA-256 per script; `verify-corpus` command detects drift. |
| R-17 | Wheel dashboard and platform state confusion | L | MITIGATED | Separate database files and schemas (ADR-0003); no shared mutable state. |
| R-18 | Clock drift on operator host | M | OPEN | Staleness checks bound decision ages; time-sync check is documented operator duty (docs/OPERATIONS.md); automated NTP verification not implemented. |
| R-19 | Session usage limits interrupting long autonomous builds | L | ACCEPTED | Workflow resume caching + checkpoint commits made recovery cheap (observed and exercised during this build). |
| R-24 | Writer lease is never renewed in production, and is not a fencing token | C | OPEN (M2 prerequisite) | `WriterLease.renew()` has no production caller (`grep '\.renew('` over `src/` is empty), so the 30-second lease silently expires mid-session while `BackendState.writer` stays True; a second backend can then acquire it while the first still believes it holds it. The lease token is never passed to or checked by DB writes or the broker send, so it is an advisory lock, not a fencing token. Harmful today; **unacceptable under unattended autonomy**, where no human is watching for the split-brain. Found by the M0 audit; must be fixed in M2 before any autonomous submission. |
| R-25 | `max_opening_orders_per_day` is inert | H | OPEN (M2 prerequisite) | `BrokerRiskEvidenceProvider.gather` never sets `opening_orders_today`, so it defaults to 0 and the check always passes; `OrderIntentRepository.count_opening_since` has zero callers and filters SELLs only, so BUY-opening families would not be counted even if wired. ADR-0010 §4 claims this was wired — it was not; that claim is corrected here. An unthrottled decision loop is exactly what this limit exists to bound. |
| R-26 | `market_open` is permanently AMBIGUOUS in production | H | OPEN (M2 prerequisite) | `BrokerRiskEvidenceProvider._broker_confirms_open` hard-returns `None`, so equities/options never receive broker session evidence. It fails **closed** (no live equity/option order can currently pass risk at all), so it is not a live-money hazard today — but it means the session gate has never actually been exercised, and it blocks M6/M7 autonomous stock operation until real evidence is supplied. |
| R-27 | Option deliverable verification comes only from `DemoBroker` | H | OPEN (M2/M8 prerequisite) | `deliverable_verified=True` is set only by the demo adapter; neither IBKR adapter populates it, so `standard_deliverable_verified` FAILs every option order against a real gateway. Fail-closed, but it means the entire option path is unproven outside demo — load-bearing for M8 (autonomous options). |
| R-28 | Dormant second submission path in the deterministic plane | H | OPEN (M2 decision required) | `chronos/execution/brokers/ibkr_paper.py` holds a working `placeOrder`/`cancelOrder` with a **hardcoded** `order.transmit = True` (:120) that the single-transmit-site AST test does not scan, and a `request_cancel` that re-verifies nothing. It is constructed nowhere in production (the only `ExecutionEngine` wiring passes `NullExecutionBroker`), and its docstring's "ONLY code path" claim is stale. One wiring change would create a second transmit plane with none of the ADR-0009 gates. M2 must retire it, quarantine it, or prove its isolation structurally. |
| R-29 | Autonomous model authority materially expands risk | C | OPEN (ACCEPTED, owner-directed) | ADR-0016/D-16 create the first code path by which a non-deterministic component can originate an order. Mitigations are structural and layered: one decision type that cannot express an order, one gateway, one transmit site, model isolation outside the broker-writing process, an expiring deny-by-default owner mandate, per-family promotion, and an unconditional deterministic veto. Residual risk is real and accepted by explicit owner directive; it is bounded by mandate limits, the kill switch, and the drawdown breaker, and reduced further only by the M2-M10 gates. |
| R-30 | Prompt injection into model decisions | H | OPEN (M4 scope) | Evidence derived from external text (news, filings, third-party content) is an untrusted input to a non-deterministic component; a successful injection can produce a malicious-but-well-formed `AITradeDecision`. Controls: typed decisions only (free-form text is never parsed into orders), redacted/versioned/hash-pinned EvidenceBundles, allowlisted read-only tools, and — the control that actually holds — the deterministic kernel, which independently re-derives contract, size, collateral, and every limit and can veto. Explicit malformed-output and injection tests are owed by M4 and are a frozen promotion criterion. |
| R-31 | Model repeatedly re-submitting a refused decision | M | OPEN (M2 scope) | A model that does not accept a rejection could retry in a loop, burning rate limits or finding a transient window. ADR-0016 §2 requires that a refusal cannot be overridden, reinterpreted, or routed around, and that re-submission is itself bounded, rate-limited, and audited. Enforcement lands with the gateway in M2. |
